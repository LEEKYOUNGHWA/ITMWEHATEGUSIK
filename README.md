# GS강서타워 커피·점심 돌림판

Vue 3 + Vite + Node.js + WebSocket으로 만든 사내 모임방입니다. 상단 탭 순서는 **커피방 → 점심방 → 정보등록방**입니다. 커피·점심의 후보와 돌림판은 따로 관리하고, 선정 이력·채팅·사용자 정보는 공용으로 사용합니다.

## 개발 가이드 — 사람과 AI 공통

### 포트·브랜치·데이터

| 용도 | 브랜치 / 코드 | 포트 | 데이터 | 명령 |
| --- | --- | --- | --- | --- |
| 공유 서비스 | GitHub `main` → `.deploy/releases` | **3000** | `data/` | 배포 담당 PC의 `npm run auto:start` |
| 로컬 개발 | **`codex/작업명`** → 현재 작업 폴더 | **3001** | **`.dev-data/`** | **`npm run dev`** |

사람과 AI 모두 `codex/catalog-search`처럼 작업 내용이 드러나는 브랜치에서 개발합니다. `main`은 서비스 기준 브랜치입니다. 작업 브랜치 푸시는 서비스에 반영되지 않고, `main`에 병합·푸시하면 자동 배포가 기본 15분 간격으로 확인해 설치·테스트·빌드·기동 검사 후 3000번에 반영합니다.

### 처음 받은 사람: 원본 파일 없이 시작하기

Node 22.12 이상(권장: 24)과 Git을 준비하고 실행합니다. `my-task`는 작업 이름으로 바꾸세요.

```sh
git clone https://github.com/LEEKYOUNGHWA/ITMWEHATEGUSIK.git
cd ITMWEHATEGUSIK
git switch -c codex/my-task
npm ci
npm run dev
```

이미 받은 저장소라면 clone을 반복하지 않고 해당 프로젝트 폴더를 사용합니다. 이 PC에서 Node 명령이 안 잡히면 새 PowerShell에서 `$env:Path = "$env:LOCALAPPDATA\lunch-node\bin;$env:Path"`를 먼저 실행합니다.

접속은 **http://localhost:3001**입니다. `npm run dev`가 3001번과 `.dev-data/`를 자동 지정하므로 환경변수를 따로 설정할 필요가 없습니다. 터미널에 운영 환경변수가 남아 있어도 개발은 분리된 경로를 사용합니다. 화면(Vue·CSS) 수정은 자동 반영됩니다. server·scripts·샘플 초기화 코드를 수정했다면 개발 서버를 종료하고 다시 실행하세요. 종료는 실행 터미널에서 **Ctrl+C**이며, 별도 프로세스의 3000번 서비스는 계속 동작합니다.

**서울 원본 CSV와 운영 data 폴더는 개발·테스트·빌드에 필요하지 않습니다.** 첫 개발 실행에서 다음 파일을 자동 준비합니다.

- `config/dev-seoul.csv`: 저장소에 포함된 가상 가게 7곳. 모두 `[개발샘플]` 표시가 있으며 실제 업소 자료가 아닙니다.
- `.dev-data/source/seoul.csv`와 `source-index.json`: 샘플 사본과 검색용 가공 목록.
- `.dev-data/restaurants.json`: 커피·점심 각 2곳의 등록 후보. 기본 추첨, 전체 검색, 미노출 포함 랜덤, 반경, 원본 다시 읽기를 개발할 수 있습니다.
- 개발 채팅·프로필·설정·이력도 `.dev-data/`에 저장합니다. 재실행 시 기존 개발 파일은 덮어쓰지 않습니다.

실제 서울 자료의 업소 수·분포나 대용량 성능은 샘플만으로 검증할 수 없습니다. 해당 작업에만 개발용 원본 사본을 `.dev-data/source/seoul.csv`에 넣고 개발 화면의 ‘원본 다시 읽기’를 사용하세요. 가공 목록도 따로 복사한다면 서버를 종료한 상태에서 `.dev-data/source-index.json`에 넣고, CSV와 같은 자료의 목록인지 확인하세요. 원본 다시 읽기는 CSV 기준으로 목록을 다시 만듭니다.

`.dev-data/`, 운영 `data/`, `.deploy/`는 Git에서 제외합니다. 운영 파일을 개발 테스트에 사용하지 않습니다. `npm start`는 수동 서비스 실행용이므로 개발에는 `npm run dev`를 사용하세요.

### 기존 작업자가 새 작업을 시작할 때

```sh
git branch --show-current
git status --short
```

기존에 해당 작업용 `codex/...` 브랜치가 있으면 이어서 사용합니다. 사용자 변경이 남아 있으면 내용을 구분해 보존하고, 임의로 reset·clean·복구·stash하지 않습니다. **작업 폴더가 깨끗하고 새 작업을 시작할 때만** 다음 순서로 진행합니다.

```sh
git switch main
git pull --ff-only origin main
git switch -c codex/my-task
npm ci
npm run dev
```

### 검증·공유·서비스 반영

기능 변경은 `npm test`, `npm run build`와 3001번의 해당 흐름으로 확인합니다. 문서만 수정했다면 내용과 `git diff --check`를 확인합니다. 테스트는 임시 가상 데이터를 사용하므로 실제 CSV 없이 실행됩니다.

커밋 전 `git diff`와 `git status --short`로 확인하고 **작업 파일만 지정하여** 스테이징합니다. 특히 `config/restaurants.json`의 사용자 변경을 별도 요청 없이 포함하지 않습니다. 작업 브랜치에서 커밋한 다음 `git push -u origin HEAD`로 공유하고, GitHub에서 `main` 대상 PR을 검토·병합합니다. `main` 병합·푸시는 서비스 배포를 유발하므로 개발 브랜치 푸시와 구분하세요.

AI도 먼저 `AGENTS.md`를 읽고 같은 절차를 따릅니다. 일반 개발을 위해 3000번 서버나 감시 프로세스를 종료·재시작하지 않습니다. 커밋·푸시·main 병합은 사용자가 요청한 범위를 따릅니다.

## 로컬 자동 배포 (PowerShell)

2026-10-30 사용자 요청으로 이 PC에서 **자동 배포를 시작했습니다.** 실제 설치·테스트·빌드·임시 포트 기동과 운영 전환을 확인했고, 별도 로컬 저장소에서 실패·재시도·복구·데이터 보존·중지를 검증했습니다. 현재 실행 상태는 `npm run auto:status`로 확인하세요. Windows 부팅 자동 실행은 등록하지 않았습니다.

### 새 환경에서 최초 실행하는 순서

1. 원격 main에 이 자동 배포 코드가 포함되어 있는지 확인하세요. 첫 배포 대상에도 관리용 종료 신호와 health revision이 있어야 합니다. 이 변경 전 커밋은 검사에서 멈추게 되어 있습니다.
2. 기존에 3000번으로 실행한 npm run dev/start 터미널에서 Ctrl+C로 종료하세요. 스크립트는 다른 프로세스의 서버를 임의로 끄지 않습니다.
3. 새 PowerShell에서 프로젝트 폴더로 이동해 실행합니다.

```powershell
npm run auto:start    # 숨겨진 별도 PowerShell에서 감시·서버 운영
npm run auto:status   # 실행 단계, 적용 커밋, 마지막 오류, PID, 로그 위치
npm run auto:check    # 즉시 원격 확인 / 실패한 커밋 재시도 요청
npm run auto:stop     # 검사와 자동 서버 중지 요청
```

터미널에서 진행 상황을 직접 보려면 npm run auto:run을 사용하고, 종료는 Ctrl+C로 합니다. 백그라운드 auto:start는 ChatGPT 세션이나 시작한 터미널이 닫혀도 별도 프로세스로 동작합니다. PC 종료·로그아웃 뒤에는 다시 실행해야 하며 Windows 시작프로그램·작업 스케줄러에는 등록하지 않았습니다.

### 동작 방식

- origin/main을 기본 15분마다 fetch해서 새 커밋을 확인합니다. 브랜치에만 푸시하면 배포하지 않고 main에 병합돼야 반영됩니다. 로그인은 이 PC에 저장된 Git 인증을 사용하며 인증 실패 시 팝업을 띄우지 않고 로그에 남깁니다.
- 새 커밋은 .deploy/releases 아래의 독립적인 Git worktree에 받습니다. VS Code 작업 폴더와 미커밋 수정은 보존됩니다. 작업 폴더의 main 자체를 이동시키는 방식이 아니므로 실제 서비스 버전은 auto:status의 activeRevision으로 확인하세요.
- 새 폴더에서 npm ci → npm test → npm run build를 실행합니다. 기존 서버는 이 동안 계속 운영합니다.
- 공통 데이터의 사본으로 임시 포트에서 새 서버를 띄워 상태를 확인합니다. 검사·빌드·기동에 실패하면 기존 서버를 유지합니다.
- 검사 통과 후 진행 중인 돌림판을 잠시 기다리고, 서버에 종료 신호를 보낸 뒤 3000번에서 새 버전을 실행합니다. 브라우저는 자동 재접속합니다. 회전이 계속되면 교체를 보류합니다.
- 교체 후 기동 실패 시 이전 정상 버전으로 재시작을 시도합니다. 데이터 자체는 자동으로 이전 사본으로 덮어쓰지 않습니다.
- 빌드 실패한 동일 커밋은 반복 배포하지 않습니다. 수정 커밋을 main에 올리거나 auto:check로 재시도하세요.
- 서버 프로세스가 종료되면 마지막 정상 배포 폴더로 재시작을 시도합니다.

### 데이터와 로그

자동 배포 모드에서는 프로젝트의 data 폴더를 버전 간 공통으로 사용합니다. 이름·IP·채팅·이력은 기존 파일을 그대로 사용합니다. 후보 정보는 최초 실행 때 config/restaurants.json을 data/restaurants.json으로 한 번 복사하며, 이후 정보등록방의 저장은 data/restaurants.json에 기록합니다. 새 코드가 배포되어도 이 파일을 초기값으로 다시 덮어쓰지 않습니다. npm run dev는 3001번과 .dev-data를 자동 사용합니다. npm start는 기본 운영 data를 사용하므로 개발에는 사용하지 마세요. 후보 파일이 없는 최초 시작 때만 config/restaurants.json에서 복사합니다.

- .deploy/state.json: 감시 PID, 단계, 실제 운영 커밋과 경로, 오류
- .deploy/deploy.log: 배포 단계와 설치·테스트·빌드 결과
- .deploy/server-*.log: 서버 출력과 오류
- .deploy/runner-*.stdout.log / stderr.log: 백그라운드 감시 프로세스 로그
- .deploy/backups: 버전 교체 직전의 데이터 사본
- .deploy/releases: 검사·운영·복구용 코드와 의존성. 자동 삭제하지 않으므로 장기 운영 시 사용하지 않는 worktree를 정리하세요.

.deploy와 data는 Git에서 제외됩니다. 스크립트 자체를 업데이트하려면 작업 폴더에서 변경을 받은 뒤 auto:stop → auto:start로 감시 프로세스도 다시 시작하세요.

## 다른 사람 접속

시작할 때 `사내 접속: http://내부IP:3000` 주소가 표시됩니다. 같은 사내망에 있는 동료에게 이 주소를 알려주세요. 구현 당시 주소는 `http://10.53.85.158:3000`이며 Wi-Fi/DHCP/VPN 변경 시 달라질 수 있습니다.

- 본인 PC: http://localhost:3000
- 동료 PC: 시작 로그에 표시되는 사내 접속 주소
- 상태 확인: http://localhost:3000/api/health
- Node 서버가 0.0.0.0:3000으로 수신하므로 사내 IP로 접속할 수 있습니다. 기존에 접속 가능한 환경의 방화벽은 변경하지 않습니다.
- 회사의 무선 단말 간 통신 차단/VLAN 정책은 Windows 방화벽과 별개입니다. 호스트에서 내부 IP 접속이 되는데 다른 PC에서 안 되면 사내 네트워크 정책을 확인하세요.
- 공유기 외부 포트포워딩은 설정하지 않습니다. 로그인 없이 사내망에서 사용하는 작은 앱입니다.

로컬 개발 접속은 **http://localhost:3001**입니다. 위 개발 가이드대로 작업 브랜치에서 npm run dev를 실행하세요.

## 식당 / 좌표 관리

**정보등록방에서 누구나 가게를 수기 등록·수정하고 노출 여부를 바꿀 수 있습니다.** 저장 즉시 모든 접속자에게 반영되고 `data/restaurants.json`에 저장되므로 서버 재시작 후에도 남습니다. 동시에 수정하면 먼저 저장한 내용을 덮어쓰지 않도록 재수정을 안내합니다. 회전 중에는 정보 변경을 잠깐 막습니다.

이 파일은 UTF-8 JSON 배열이며 `room`이 `coffee`면 커피방, `lunch`면 점심방입니다. 기존 데이터에서 room이 없으면 점심방으로 처리합니다. 파일을 직접 편집했을 때만 서버를 재시작하세요. 기존 등록 정보는 유지하며, 정보등록방 전체 목록에서 공공데이터 가게의 노출을 켜거나 수기로 등록할 수 있습니다.

```json
{
  "id": "r13",
  "room": "lunch",
  "name": "새 식당",
  "category": "한식",
  "description": "대표 메뉴를 적어주세요",
  "hours": "도보 약 5분 · 11:00–21:00",
  "address": "서울특별시 영등포구 ...",
  "lat": 37.520814,
  "lng": 126.889040,
  "source": "좌표를 확인한 페이지 주소 (선택)",
  "coordinateNote": "위치 관련 메모 (선택)"
}
```

- Google 지도에서 가게 위치를 우클릭하면 **위도, 경도**가 표시됩니다. 첫 숫자를 `lat`, 두 번째를 `lng`에 따옴표 없이 입력하세요.
- 위치를 모르겠으면 `"lat": null, "lng": null`로 둡니다. 돌림판에는 나오고 지도 핀·이동만 생략됩니다.
- `id`는 식당마다 고유하게 정하고 기존 식당의 ID를 다른 식당에 재사용하지 마세요.
- 이름/메뉴/시간/주소도 자유롭게 수정할 수 있습니다. 식당을 추가할 때는 배열 안에 객체를 하나 더 넣으세요. 식당 사이 쉼표가 필요하고 마지막 객체 뒤에는 쉼표를 붙이지 않습니다.
- 정보등록방에서 추가한 후보는 해당 방의 돌림판 후보로 자동 선택됩니다. 기존 후보의 체크 상태는 유지됩니다. 카페와 식당은 각 방에서 2곳 이상 선택해야 돌릴 수 있습니다.
- 삭제된 식당의 과거 선정 이력은 당시 이름과 정보로 남습니다.
- 잘못된 JSON, 중복 ID, 잘못된 좌표는 시작할 때 식당 이름/파일명과 함께 오류를 표시합니다.

현재 12곳 중 10곳에 주소를 대조한 좌표를 넣었습니다. 건물 대표 좌표가 포함되어 실제 가게 출입구와 차이가 있을 수 있습니다. 각 항목의 `source`, `addressSource`, `coordinateNote`에서 근거를 확인할 수 있습니다. 소문난식당은 주소만 입력했고, 서여산은 원본 이름으로 지점을 확인하지 못해 좌표를 비웠습니다. 원본의 거리와 영업시간은 갱신하지 않았으니 직접 확인해 주세요. 정보등록방에서 수정할 수 있습니다.

배경의 GS강서타워는 선유로 75 건물 대표 위치를 사용합니다. 출처: https://rlh.purpleo.kr/article/5101

## 화면

- 중앙: 지도 위에 떠 있는 돌림판 카드, 선정 결과, 공유 식당 체크 목록. 헤더에서 돌림판을 숨기거나 다시 표시할 수 있으며 상태를 브라우저에 기억합니다.
- 우측: 화면 가장자리에 고정된 선정 이력 / 채팅 패널, 접속자 목록. 헤더의 버튼이나 패널의 → 버튼으로 접고 펼칠 수 있으며 브라우저에 상태를 기억합니다.
- 우측 기록 패널 하단: 내 이름, 사람 이모지, 공용 채팅 입력 (Enter로 전송). 기록 스크롤과 별개로 항상 아래에 붙어 있습니다.
- 헤더: 스크롤해도 화면 상단에 고정됩니다. 좁은 화면에서는 기록 패널이 처음에 접혀 있습니다.
- 상단 ◐ 버튼: 시스템 / 다크 / 라이트 테마 순환
- 커서: 중앙 공유 영역에서 이름·이모지와 함께 움직입니다. 각 사용자의 마지막 채팅은 커서 옆 말풍선에 시간 제한 없이 표시되며, 새 메시지를 보내면 교체됩니다. 패널에서도 기록을 읽을 수 있습니다.
- 지도: OpenStreetMap + Leaflet 사용. 넓은 화면에서는 기록 패널과 지도가 겹치지 않으며, 패널을 접으면 지도 영역이 넓어집니다. 당첨 핀은 돌림판을 피해 보이는 영역으로 이동합니다. 빈 지도에서 드래그로 이동하고 휠·오른쪽 +/− 버튼·모바일 두 손가락으로 확대·축소할 수 있습니다. `전체 보기` 버튼은 식당 전체 범위로 돌아갑니다. 직접 움직인 지도 시점은 각자 유지하며 다음 회전 시작/당첨 때는 공유 연출이 다시 적용됩니다. 회전 시작 시 전체 범위로 복귀하고, 당첨되면 해당 식당으로 이동·확대합니다. 외부 지도 접속이 막히면 크림색 배경에서 돌림판은 계속 작동합니다. Google API 키가 필요하지 않습니다.

지도 출처 표시는 유지해야 합니다. OSM 타일은 일반 브라우저 캐시 정책을 따르며 미리 다운로드하지 않습니다. https://operations.osmfoundation.org/policies/tiles/

## 데이터 보관

서버가 만드는 `data` 폴더:

- `settings.json`: coffee/lunch 방별 체크 상태, 마지막 각도, 진행 중 회전. 이전 단일 방 설정은 점심방으로 복원됩니다.
- `history.jsonl`: 커피·점심 공용 선정 이력 (한 줄에 JSON 한 건, room으로 구분). 이전 이력은 점심으로 표시됩니다.
- `chat.jsonl`: 모든 방에서 공유하는 채팅 내역 (한 줄에 JSON 한 건)
- `profiles.json`: 접속 IP별 고유 프로필 ID·이름·이모지·마지막 말풍선·수정 시각

파일에 계속 기록하며 화면에서는 이력 최근 500건과 채팅 최근 200건을 보여줍니다. SQLite/외부 DB는 사용하지 않습니다. 이름·이모지는 접속 IP를 기준으로 서버의 profiles.json에 기억하며 각 브라우저의 localStorage에도 저장합니다. 같은 IP로 재접속하면 서버에 저장된 정보가 우선 적용됩니다. 우측 패널 하단에서 이름이나 이모지를 변경하면 저장되며 같은 IP의 열린 탭에도 반영됩니다. IP가 바뀌면 다른 항목으로 취급하고, 처음 보는 IP에는 브라우저에 기억된 이름·이모지를 가져옵니다. 여러 사람이 같은 IP를 공유하면 하나의 프로필을 사용합니다. 서버는 실제 소켓의 IP를 사용하고 X-Forwarded-For 같은 요청 헤더는 신뢰하지 않습니다. IP 정보는 화면이나 상태 API에 노출하지 않습니다. 새 채팅과 선정 이력은 고유 프로필 ID로 연결하므로 이름·이모지를 바꾸면 기존 기록에도 현재 정보가 표시됩니다. 이 기능 적용 전에 생성되어 프로필 ID가 없는 기록은 작성 당시 이름을 유지합니다. 마지막 말풍선은 새 메시지를 보낼 때 교체되며 재접속 후에도 복원됩니다. 커서 좌표와 온라인 상태는 저장하지 않습니다. 자료를 백업하려면 서버 종료 후 `config`와 `data` 폴더를 복사하세요.

서버가 회전 도중 꺼졌다면 재시작 때 저장된 회전 결과를 확정하고 이력에 한 번만 남깁니다. 저장 실패 시 화면에 알림이 표시되며 이력 저장이 복구될 때까지 다음 회전을 막습니다. 파일이 손상되면 시작 시 해당 파일과 줄 번호를 알려주며 임의로 기록을 삭제하지 않습니다.

## 주변 음식점 원본 데이터와 교체 방법

출처는 [공공데이터포털 — 소상공인시장진흥공단 상가(상권)정보](https://www.data.go.kr/data/15083033/fileData.do)입니다. 최초 적용 파일은 **소상공인시장진흥공단_상가(상권)정보_서울_202606.csv**이고, 다운로드 폴더 `소상공인시장진흥공단_상가(상권)정보_20260630`에서 서울 파일만 가져왔습니다. 링크는 출처 안내용이며 앱이 사이트에서 자동 다운로드하지 않습니다.

- 원본 보관 위치: 프로젝트 루트의 **`data/source/seoul.csv`** (UTF-8 CSV, 내용은 변환하지 않음)
- 가공 결과: `data/source-index.json` — GS강서타워 기준 최대 2km 안 음식업 전체와 적용 시각·행 수·SHA-256
- 사용자 관리 정보: `data/restaurants.json` — 수기 등록, 공공데이터와 연결한 가게, 방 변경, 노출·미노출, 사유, 직접 수정한 정보
- 방별 반경·추첨 방식·체크 상태: `data/settings.json`
- 위 파일은 모두 `data/` 아래에 있으며 **Git에 올리지 않습니다.** 코드만 받아서는 원본과 운영 정보가 복원되지 않으므로 로컬 `data` 폴더를 별도로 백업하세요.

### 새 데이터로 교체하기

1. 위 출처에서 새 자료를 내려받아 압축을 풉니다. **서울 CSV만** 사용하며 ZIP이나 다른 지역 파일은 넣지 않습니다.
2. 기존 `data/source/seoul.csv`를 필요하면 별도 백업한 뒤, 새 서울 CSV를 **같은 위치와 파일명**으로 교체합니다. 복사가 끝날 때까지 기다립니다.
3. 실행 중인 앱의 **정보등록방 → 원본 다시 읽기**를 누릅니다. 서버 재시작이나 명령어 실행은 필요 없습니다.
4. 적용 시각·원본 행 수·주변 가게 수를 확인합니다. 모든 접속자의 목록에 반영됩니다.

원본은 명시적으로 적용할 때만 별도 작업 스레드에서 읽습니다. 앱 시작이나 화면 검색 때 CSV 전체를 다시 읽지 않습니다. 처리 중 중복 실행과 새 추첨은 막고, CSV가 잘못됐거나 저장에 실패하면 기존 정상 목록을 유지합니다. 채팅·사용자 정보·선정 이력은 건드리지 않습니다.

상가업소번호로 원본 연결을 기억하며, 원본을 교체해도 사용자가 정한 노출 상태·수정 내용·수기 등록을 보존합니다. 등록된 가게의 정보는 사용자가 관리하는 값이 우선합니다. 새 가게는 미노출로 검색 목록에 추가되며 자동으로 노출하지 않습니다. 최신 **2km 원본 목록**에서 빠진 등록 가게는 ‘미확인’으로 표시하고 추첨에서 제외합니다. 폐업을 뜻하는 표시는 아닙니다. 계속 사용할 가게는 수정 화면에서 원본 연결을 해제하고 수기 등록 가게로 전환할 수 있습니다. 비슷한 이름의 기존 가게와 자동 병합하지 않습니다.

### 노출과 추첨 방식

- **정보등록방**: 2km 안 음식업 전체를 40개씩 보여줍니다. 이름·주소·업종·방·거리·노출 여부로 검색하고, 가게별 **노출 체크**를 켜거나 끌 수 있습니다. 원본 업종 분류가 애매한 가게는 수정에서 방을 고르세요. 수기 등록도 같은 화면에서 가능합니다.
- **노출된 가게만**: 노출을 켠 등록 가게 중 오늘의 후보 체크가 켜져 있고, 현재 방의 반경 안에 있는 곳만 추첨합니다.
- **미노출 포함 전체 랜덤**: 방별 기본 업종에 해당하는 공공데이터와 그 방에 직접 등록한 가게를 합쳐 추첨합니다. 미노출 사유가 있는 가게와 오늘의 후보 체크를 끈 곳도 포함합니다. 원본으로 연결한 가게는 중복 추첨하지 않지만, 별도로 수기 등록한 동일 가게는 자동 병합하지 않습니다.
- 전체 랜덤에서도 각 가게의 당첨 확률은 같습니다. 후보가 많을 때는 무작위로 최대 12곳을 먼저 뽑아 돌림판에 표시한 뒤 그 안에서 추첨합니다. 표시되는 후보와 최종 결과는 모두에게 공유됩니다.
- 반경은 지도 상단에서 **0~2km, 0.1km 단위**, 기본 1km로 조절합니다. GS강서타워 고정 좌표 기준 **직선거리**이며 지도 중심을 옮겨도 기준점은 바뀌지 않습니다. 방별로 저장되고 접속자에게 공유됩니다.
- 반경 밖 후보는 삭제되지 않고 넓히면 다시 참여합니다. 좌표 미등록·원본 미확인 가게는 두 방식 모두 추첨에서 제외합니다. 가능한 후보가 2곳 미만이면 돌릴 수 없습니다.
- 회전 중에는 후보·노출·반경·추첨 방식·원본을 변경할 수 없습니다. 지도 드래그·확대와 채팅은 계속 가능합니다.

기본 업종은 `config/source-categories.json`에서 관리합니다. 커피는 카페만, 점심은 한·중·일·양식 식사류와 분식·버거·피자·샌드위치 등을 포함하고 주점·구내식당·고기구이·치킨·족발·횟집은 기본 추첨 업종에서 뺍니다. 이 가게들도 정보등록방 전체 목록에는 보이며 원하는 방에 노출 등록할 수 있습니다. 설정 파일을 변경한 뒤 원본을 다시 읽으면 검색 분류에 적용됩니다.

원본에는 가격·평점·영업시간·실시간 영업 여부가 없습니다. 비싸거나 취향에 맞지 않는 곳은 미노출 사유로 관리하세요. **전체 랜덤은 미노출도 포함**하므로 이런 곳을 빼고 싶으면 ‘노출된 가게만’을 사용하세요.

### 기존 후보 저장 위치 전환

이 버전부터 일반 실행도 `data/restaurants.json`에 저장합니다. 파일이 없는 최초 시작 때만 기존 `config/restaurants.json`의 최신 내용을 복사하고, 이후에는 운영 JSON을 유지합니다. 기존 config 파일은 덮어쓰지 않습니다. `RESTAURANTS_FILE` 환경변수를 지정했다면 지정한 경로가 우선합니다. 자동 배포에서도 공통 `DATA_DIR` 아래 원본·가공 목록·운영 JSON을 사용합니다.


## Teams 결과 공유

화면 상단의 **Teams에 결과 공유** 버튼은 식당명·설명·주소·영업시간·추첨 시간과 고정 결과 링크를 텍스트로 복사한 뒤 지정한 Teams 채팅방을 엽니다. Teams에서 Ctrl+V 후 직접 전송합니다. HTTP에서는 기존 브라우저 복사 명령을 사용하며, 복사를 허용하지 않는 브라우저에서는 공유 문구를 선택한 뒤 Ctrl+C로 복사할 수 있습니다. 팝업이 차단되면 미리보기의 채팅방 열기 링크를 사용합니다. 별도 Teams API 등록이나 이미지 클립보드 권한은 필요하지 않습니다.

공유 설정도 개발·운영을 분리합니다. npm run dev의 3001번 개발 서버는 .dev-data/sharing.json, 3000번 자동 배포 서비스는 data/sharing.json을 사용합니다. 개발 서버가 운영 공유 설정을 자동으로 복사하지 않습니다. 설정이 없으면 문구 복사만 제공하며, 개발용 Teams 연결을 시험하려면 개발 설정에 테스트용 채팅방 주소를 넣으세요. 두 설정 파일은 Git 제외 대상이며 실제 단체 채팅방 주소를 소스에 넣지 않습니다.

~~~json
{
  "teamsUrl": "https://teams.microsoft.com/l/chat/<채팅방ID>/conversations",
  "publicOrigin": "http://<사내서버IP>:3000"
}
~~~

Teams 메시지의 링크 복사 주소를 teamsUrl에 사용할 수 있습니다. publicOrigin은 다른 PC에서도 접속할 수 있는 주소를 지정합니다. 생략하면 현재 접속 주소를 쓰므로 localhost에서 공유할 때 주의합니다. Teams 주소가 없으면 문구 복사만 제공합니다. 설정은 요청마다 읽으므로 수정 후 서버 재시작은 필요하지 않습니다. 새 API 코드를 처음 적용할 때는 서버 재시작이 필요합니다.

공유 링크는 /?result=<추첨ID>이며 저장된 history.jsonl의 당시 식당 정보로 조회합니다. 최근 이력 500건 범위를 벗어나거나 서버를 재시작해도 원본 이력이 남아 있으면 조회됩니다. 원본 이력을 삭제하면 해당 링크는 더 이상 조회되지 않습니다. 링크를 여는 사람도 사내망에 접속해야 합니다. 커피방과 점심방의 결과를 각각 공유할 수 있습니다.
