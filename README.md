# GS강서타워 커피·점심 돌림판

Vue 3 + Vite + Node.js + WebSocket으로 만든 사내 모임방입니다. 상단 탭 순서는 **커피방 → 점심방 → 정보등록방**입니다. 커피·점심의 후보와 돌림판은 따로 관리하고, 선정 이력·채팅·사용자 정보는 공용으로 사용합니다.

## 실행 / 종료

이 PC에는 기존 Node 실행 파일을 재사용한 로컬 실행 환경을 `C:\Users\rudgh\AppData\Local\lunch-node\bin`에 준비했습니다. 사용자 PATH도 등록했습니다. **새 PowerShell/터미널에서** 실행하세요. 기존 VS Code 터미널에서 명령이 안 잡히면 VS Code까지 다시 열거나 아래 PATH 설정을 한 번 실행하세요.

```powershell
$env:Path = "$env:LOCALAPPDATA\lunch-node\bin;$env:Path"
cd "C:\Users\rudgh\Documents\GS강서타워 점심 돌림판"
npm run dev
```

평소에는 폴더에서 `npm run dev`만 실행하면 됩니다. Vue 화면과 공유 서버가 함께 켜지고 코드 수정도 바로 반영됩니다. 종료는 **실행한 터미널에서 Ctrl+C**입니다. 별도의 백그라운드 서비스나 부팅 자동 실행은 등록하지 않았습니다. 이 창을 닫거나 PC를 끄면 다른 사람도 접속할 수 없습니다.

다른 PC로 프로젝트를 복사할 때에는 Node 22.12 이상(권장: 24)을 설치하고 최초 한 번 아래 명령을 실행합니다.

```powershell
npm install
npm run dev
```

화면을 빌드해서 서비스하려면:

```powershell
npm run build
npm start
```

개발 실행과 빌드 실행은 같은 3000번 포트를 쓰므로 동시에 실행하지 마세요. 현재 어느 쪽이 켜졌는지는 해당 터미널의 실행 명령으로 확인할 수 있습니다. 브라우저 http://localhost:3000/api/health 에서 서버 응답 여부도 확인할 수 있습니다.

## 다른 사람 접속

시작할 때 `사내 접속: http://내부IP:3000` 주소가 표시됩니다. 같은 사내망에 있는 동료에게 이 주소를 알려주세요. 구현 당시 주소는 `http://10.53.85.158:3000`이며 Wi-Fi/DHCP/VPN 변경 시 달라질 수 있습니다.

- 본인 PC: http://localhost:3000
- 동료 PC: 시작 로그에 표시되는 사내 접속 주소
- 상태 확인: http://localhost:3000/api/health
- Node 서버가 0.0.0.0:3000으로 수신하므로 사내 IP로 접속할 수 있습니다. 기존에 접속 가능한 환경의 방화벽은 변경하지 않습니다.
- 회사의 무선 단말 간 통신 차단/VLAN 정책은 Windows 방화벽과 별개입니다. 호스트에서 내부 IP 접속이 되는데 다른 PC에서 안 되면 사내 네트워크 정책을 확인하세요.
- 공유기 외부 포트포워딩은 설정하지 않습니다. 로그인 없이 사내망에서 사용하는 작은 앱입니다.

포트 변경은 실행할 터미널에서 설정합니다.

```powershell
$env:PORT = "3100"
npm run dev

```

## 식당 / 좌표 관리

**정보등록방에서 누구나 후보를 추가·수정·삭제할 수 있습니다.** 저장 즉시 모든 접속자에게 반영되고 `config/restaurants.json`에 저장되므로 서버 재시작 후에도 남습니다. 동시에 수정하면 먼저 저장한 내용을 덮어쓰지 않도록 재수정을 안내합니다. 회전 중에는 정보 변경을 잠깐 막습니다.

이 파일은 UTF-8 JSON 배열이며 `room`이 `coffee`면 커피방, `lunch`면 점심방입니다. 기존 데이터에서 room이 없으면 점심방으로 처리합니다. 파일을 직접 편집했을 때만 서버를 재시작하세요. 기존 12개 식당은 점심방에 있으며, 커피방은 정보등록방에서 직접 후보를 등록하면 됩니다.

```json
{
  "id": "r13",
  "room": "lunch",
  "name": "새 식당",
  "category": "한식",
  "description": "대표 메뉴를 적어주세요",
  "hours": "도보 약 5분 · 11:00–21:00",
  "address": "서울특별시 영등포구 ...",
  "lat": 37.520814,
  "lng": 126.889040,
  "source": "좌표를 확인한 페이지 주소 (선택)",
  "coordinateNote": "위치 관련 메모 (선택)"
}
```

- Google 지도에서 가게 위치를 우클릭하면 **위도, 경도**가 표시됩니다. 첫 숫자를 `lat`, 두 번째를 `lng`에 따옴표 없이 입력하세요.
- 위치를 모르겠으면 `"lat": null, "lng": null`로 둡니다. 돌림판에는 나오고 지도 핀·이동만 생략됩니다.
- `id`는 식당마다 고유하게 정하고 기존 식당의 ID를 다른 식당에 재사용하지 마세요.
- 이름/메뉴/시간/주소도 자유롭게 수정할 수 있습니다. 식당을 추가할 때는 배열 안에 객체를 하나 더 넣으세요. 식당 사이 쉼표가 필요하고 마지막 객체 뒤에는 쉼표를 붙이지 않습니다.
- 정보등록방에서 추가한 후보는 해당 방의 돌림판 후보로 자동 선택됩니다. 기존 후보의 체크 상태는 유지됩니다. 카페와 식당은 각 방에서 2곳 이상 선택해야 돌릴 수 있습니다.
- 삭제된 식당의 과거 선정 이력은 당시 이름과 정보로 남습니다.
- 잘못된 JSON, 중복 ID, 잘못된 좌표는 시작할 때 식당 이름/파일명과 함께 오류를 표시합니다.

현재 12곳 중 10곳에 주소를 대조한 좌표를 넣었습니다. 건물 대표 좌표가 포함되어 실제 가게 출입구와 차이가 있을 수 있습니다. 각 항목의 `source`, `addressSource`, `coordinateNote`에서 근거를 확인할 수 있습니다. 소문난식당은 주소만 입력했고, 서여산은 원본 이름으로 지점을 확인하지 못해 좌표를 비웠습니다. 원본의 거리와 영업시간은 갱신하지 않았으니 직접 확인해 주세요. 정보등록방에서 수정할 수 있습니다.

배경의 GS강서타워는 선유로 75 건물 대표 위치를 사용합니다. 출처: https://rlh.purpleo.kr/article/5101

## 화면

- 중앙: 지도 위에 떠 있는 돌림판 카드, 선정 결과, 공유 식당 체크 목록. 헤더에서 돌림판을 숨기거나 다시 표시할 수 있으며 상태를 브라우저에 기억합니다.
- 우측: 화면 가장자리에 고정된 선정 이력 / 채팅 패널, 접속자 목록. 헤더의 버튼이나 패널의 → 버튼으로 접고 펼칠 수 있으며 브라우저에 상태를 기억합니다.
- 우측 기록 패널 하단: 내 이름, 사람 이모지, 공용 채팅 입력 (Enter로 전송). 기록 스크롤과 별개로 항상 아래에 붙어 있습니다.
- 헤더: 스크롤해도 화면 상단에 고정됩니다. 좁은 화면에서는 기록 패널이 처음에 접혀 있습니다.
- 상단 ◐ 버튼: 시스템 / 다크 / 라이트 테마 순환
- 커서: 중앙 공유 영역에서 이름·이모지와 함께 움직입니다. 각 사용자의 마지막 채팅은 커서 옆 말풍선에 시간 제한 없이 표시되며, 새 메시지를 보내면 교체됩니다. 패널에서도 기록을 읽을 수 있습니다.
- 지도: OpenStreetMap + Leaflet 사용. 넓은 화면에서는 기록 패널과 지도가 겹치지 않으며, 패널을 접으면 지도 영역이 넓어집니다. 당첨 핀은 돌림판을 피해 보이는 영역으로 이동합니다. 빈 지도에서 드래그로 이동하고 휠·오른쪽 +/− 버튼·모바일 두 손가락으로 확대·축소할 수 있습니다. `전체 보기` 버튼은 식당 전체 범위로 돌아갑니다. 직접 움직인 지도 시점은 각자 유지하며 다음 회전 시작/당첨 때는 공유 연출이 다시 적용됩니다. 회전 시작 시 전체 범위로 복귀하고, 당첨되면 해당 식당으로 이동·확대합니다. 외부 지도 접속이 막히면 크림색 배경에서 돌림판은 계속 작동합니다. Google API 키가 필요하지 않습니다.

지도 출처 표시는 유지해야 합니다. OSM 타일은 일반 브라우저 캐시 정책을 따르며 미리 다운로드하지 않습니다. https://operations.osmfoundation.org/policies/tiles/

## 데이터 보관

서버가 만드는 `data` 폴더:

- `settings.json`: coffee/lunch 방별 체크 상태, 마지막 각도, 진행 중 회전. 이전 단일 방 설정은 점심방으로 복원됩니다.
- `history.jsonl`: 커피·점심 공용 선정 이력 (한 줄에 JSON 한 건, room으로 구분). 이전 이력은 점심으로 표시됩니다.
- `chat.jsonl`: 모든 방에서 공유하는 채팅 내역 (한 줄에 JSON 한 건)
- `profiles.json`: 접속 IP별 고유 프로필 ID·이름·이모지·마지막 말풍선·수정 시각

파일에 계속 기록하며 화면에서는 이력 최근 500건과 채팅 최근 200건을 보여줍니다. SQLite/외부 DB는 사용하지 않습니다. 이름·이모지는 접속 IP를 기준으로 서버의 profiles.json에 기억하며 각 브라우저의 localStorage에도 저장합니다. 같은 IP로 재접속하면 서버에 저장된 정보가 우선 적용됩니다. 우측 패널 하단에서 이름이나 이모지를 변경하면 저장되며 같은 IP의 열린 탭에도 반영됩니다. IP가 바뀌면 다른 항목으로 취급하고, 처음 보는 IP에는 브라우저에 기억된 이름·이모지를 가져옵니다. 여러 사람이 같은 IP를 공유하면 하나의 프로필을 사용합니다. 서버는 실제 소켓의 IP를 사용하고 X-Forwarded-For 같은 요청 헤더는 신뢰하지 않습니다. IP 정보는 화면이나 상태 API에 노출하지 않습니다. 새 채팅과 선정 이력은 고유 프로필 ID로 연결하므로 이름·이모지를 바꾸면 기존 기록에도 현재 정보가 표시됩니다. 이 기능 적용 전에 생성되어 프로필 ID가 없는 기록은 작성 당시 이름을 유지합니다. 마지막 말풍선은 새 메시지를 보낼 때 교체되며 재접속 후에도 복원됩니다. 커서 좌표와 온라인 상태는 저장하지 않습니다. 자료를 백업하려면 서버 종료 후 `config`와 `data` 폴더를 복사하세요.

서버가 회전 도중 꺼졌다면 재시작 때 저장된 회전 결과를 확정하고 이력에 한 번만 남깁니다. 저장 실패 시 화면에 알림이 표시되며 이력 저장이 복구될 때까지 다음 회전을 막습니다. 파일이 손상되면 시작 시 해당 파일과 줄 번호를 알려주며 임의로 기록을 삭제하지 않습니다.

## 개발 / 검증

- `src/App.vue`: 화면, 접속 상태, 커서·채팅
- `src/Wheel.vue`: 각 방의 Canvas 돌림판
- `src/CatalogEditor.vue`: 누구나 사용할 수 있는 정보등록·수정·삭제 화면
- `src/BackgroundMap.vue`: 배경 지도와 당첨 이동
- `server/index.mjs`: HTTP + WebSocket 서버
- `server/model.mjs`: 식당 검증, 회전 계산, 파일 저장

```powershell
npm test
npm run build
```

자동 테스트는 임시 폴더를 사용하므로 실제 `data`에는 테스트 대화나 이력이 남지 않습니다. 동시 접속, 중복 실행 방지, 회전 도중 접속, 재접속, 서버 재시작, 중단 회전 복구, 파일 저장 실패 후 복구, 좌표 검증을 확인합니다.
